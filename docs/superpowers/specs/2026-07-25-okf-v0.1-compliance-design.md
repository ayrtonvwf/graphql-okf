# OKF v0.1 compliance — design

Resolves [issue #8](https://github.com/ayrtonvwf/graphql-okf/issues/8).

Target: the [OKF v0.1 spec](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/ee67a5ca27044ebe7c38385f5b6cffc2305a9c1a/okf/SPEC.md)
that `GOAL-M1` §5 binds us to. Section numbers prefixed `§` refer to that spec;
`GOAL-*` and `NG-*` refer to `docs/northstar-specs/GOAL-M1.md`.

## Goal

Bring the emitter, the reconciler and the two tracked example bundles into
maximum conformance with OKF v0.1: fix one outright MUST violation, four defects
that break our own MUSTs, and the SHOULD misses worth taking. Where OKF and
`GOAL-M1` conflict, OKF wins and `GOAL-M1` is amended in the same change.

There is no OKF validator in the reference repo — the only upstream enforcement
is a producer-side check for non-empty `type`. Every requirement below therefore
has to be tested on our side or it is not enforced at all.

## Decisions

Four questions the issue deliberately left open, and the calls made:

| Question | Decision |
| --- | --- |
| `resource` semantics (§4.1 vs `GOAL-5.2`) | Per-concept URI; amend `GOAL-5.2` |
| `description` semantics (§4.1 vs `GOAL-5.2`) | First sentence; amend `GOAL-5.2` |
| `type` vocabulary (§4.1) | Title Case `GraphQL <Kind>`; `tags` unchanged |
| `# Schema` shape (§4.2, §4.3) | Markdown table under a top-level `# Schema` |

Delivery: one design doc, one staged implementation plan, one PR.
`okf/gitlab-api/` — untracked, gitignored, stale — is deleted locally.

## 1. The frontmatter contract

### 1.1 `type` — descriptive vocabulary

§4.1 asks for values that are "descriptive and self-explanatory"; every example
in the spec and in the reference bundles is a Title Case noun phrase. We emit
bare lowercase tokens (`type: object`), which are not self-explanatory in a
shared catalog and collide with any other producer's generic "object".

A new `TYPE_LABEL_BY_KIND: Record<ConceptKind, string>` lives in
`src/model/naming.ts` beside `DIRECTORY_BY_KIND`, keeping the kind mapping in the
naming module that `CLAUDE.md` names as the single source of truth. `ConceptKind`
stays the internal key everywhere; only the emitted label changes.

| kind | `type` |
| --- | --- |
| `object` | `GraphQL Object Type` |
| `interface` | `GraphQL Interface Type` |
| `union` | `GraphQL Union Type` |
| `enum` | `GraphQL Enum Type` |
| `input` | `GraphQL Input Type` |
| `scalar` | `GraphQL Scalar Type` |
| `query` | `GraphQL Query` |
| `mutation` | `GraphQL Mutation` |
| `subscription` | `GraphQL Subscription` |
| `directive` | `GraphQL Directive` |

`tags` keeps the bare kind token (`["graphql", "object"]`). It is the
machine-filterable axis, and widening it would change the meaning of every
tag-based consumer query for no conformance gain. This strengthens `GOAL-5.3`'s
"consistent, documented vocabulary" rather than conflicting with it, so
`GOAL-5.3` needs no amendment.

### 1.2 Escaping — a prerequisite, not a nicety

`src/emit/render/frontmatter.ts:8,13` interpolate `type` and `tags` unescaped,
bypassing the `JSON.stringify` path used for every other value. That is safe only
while the vocabulary is bare identifiers. A label containing a space is a legal
scalar, but a flow-sequence entry containing `,`, `]`, `#` or `: ` produces
malformed YAML and breaks §9.1.

Both move to the `JSON.stringify` path:

```yaml
type: "GraphQL Object Type"
tags: ["graphql", "object"]
```

`timestamp` (`src/emit/render/frontmatter.ts:14`) and `removedAt`
(`src/reconcile/tombstone.ts:31`) are quoted for a different reason: under YAML
1.1 — PyYAML, and js-yaml's default schema, i.e. `gray-matter` — bare
`2026-07-24T13:14:12.015Z` parses as a `datetime`, not a string. `json.dumps`
then throws `Object of type datetime is not JSON serializable`; the reference
viewer only survives it because of a `default=str` patch added in the v0.2
migration commit, whose message says the visualizer crashed on exactly this.
Round-tripping also mangles the text to `2026-07-24 13:14:12.015000+00:00`, a
`GOAL-5.5` byte-round-trip failure.

The spec's own examples show `timestamp` unquoted, so this is a deliberate
deviation for robustness, recorded in the emitter design doc.

### 1.3 `resource` — a per-concept URI

§4.1 defines `resource` as "a URI that uniquely identifies the underlying asset
the concept describes". `GOAL-5.2` currently mandates the schema origin, so all
5,047 files in a bundle carry an identical value (`src/emit/bundle.ts:57`) and
the field identifies nothing — anything keying or deduplicating by `resource`
collapses the bundle to a single asset.

The base is `ir.resource` with any existing fragment stripped; a per-concept
anchor is appended:

| Concept | Anchor | Example |
| --- | --- | --- |
| Named type | `#<TypeName>` | `https://api.example/graphql#Country` |
| Root operation field | `#<RootType>.<field>` | `https://api.example/graphql#Query.countries` |
| Directive | `#@<name>` | `https://api.example/graphql#@deprecated` |

The root operation anchor uses the schema's **declared** root type name, not a
hardcoded `Query`. `src/model/project.ts:193` already calls
`schema.getQueryType()`, so a `rootTypeName` field is threaded onto
`OperationNode` in `src/model/ir.ts`. A schema declaring
`schema { query: RootQuery }` then yields `#RootQuery.countries`.

The bundle-wide origin is not lost — it moves to the root `index.md` frontmatter
(§1.5).

There are no per-field concept files, so the anchor vocabulary above is complete:
concepts are exactly the ten `ConceptKind` values.

### 1.4 `description` — the first sentence

§4.1 defines `description` as "a single sentence… used by `index.md` generators,
search snippets, and previews". `GOAL-5.2` currently mandates the full
documentation string: 301 emitted descriptions contain paragraph breaks and the
longest is 449 characters. The tell that the value is the wrong shape is that our
own index generator already calls `firstLine()` to work around it
(`src/emit/bundle.ts:36-38`).

The rule must be deterministic (`NG-6` forbids any runtime inference), so it is
an explicit regex, not a segmentation library:

1. If the docstring is `null`, or trims to the empty string, the value is `null`.
2. Collapse all whitespace runs (including newlines) to single spaces, and trim.
3. Cut at the first match of `/[.!?](\s|$)/`, keeping the terminator.
4. If there is no match, use the whole collapsed string.

Rule 3 is intentionally naive: an abbreviation such as `e.g.` cuts early. The
alternative — an abbreviation dictionary — is unbounded, locale-sensitive, and
would make the output depend on a word list rather than the schema. An early cut
is a shorter preview; the full text is never lost, because the verbatim
multi-paragraph docstring stays in the body (`src/emit/render/body.ts:38-40`), so
`GOAL-6.3` continues to hold.

Rule 1 also fixes issue item 3e. `src/model/project.ts:335` and its siblings use
`?? null`, so a GraphQL description that is the empty string survives as `""` and
is emitted, because `src/emit/render/frontmatter.ts:9` only checks `!== null`.
Real cases exist in the GitLab bundle (`ValueStreamAnalyticsMetric`,
`ValueStreamAnalyticsDateMetric`), which also get a stray empty paragraph in the
body. Normalizing with `description?.trim() || null` at the model layer fixes
both the frontmatter and the body in one place.

### 1.5 The bundle-root `index.md`

§11 makes the bundle-root `index.md` the only index where frontmatter is
permitted, for declaring the targeted OKF version. Today an `okf_version` added
by hand is silently destroyed: `src/reconcile/plan.ts:45-47` claims every
`index.md` as machine-owned, and `src/reconcile/frontmatter.ts:72-77` returns the
rendered side verbatim whenever the **rendered** side has no frontmatter block —
always true for an index — so the existing block is dropped and
`plan.ts:117-121` rewrites the file.

The root index gains a frontmatter block:

```yaml
---
okf_version: "0.1"
resource: "https://countries.trevorblades.com/graphql"
---
```

`okf_version` and `resource` join `MACHINE_KEYS` in
`src/reconcile/frontmatter.ts:5-14`. Once the rendered side has a block, the
merge stops discarding the existing one. Both values are constants for a given
run, so `GOAL-8.1`/`NG-6` are unaffected.

Every other `index.md` stays frontmatter-free per §6.

This is also a prerequisite for future v0.2 support: bundle-version detection
depends on `okf_version` surviving a round-trip.

### 1.6 `GOAL-M1` amendments

`GOAL-5.2` is edited in the same PR, each bullet citing issue #8:

- `resource` — "MUST uniquely identify the concept's schema element as a URI
  fragment on the schema origin" (was: "MUST point at the source of truth (the
  endpoint URL or SDL origin)"). The bundle-wide origin moves to the root
  `index.md`.
- `description` — "MUST be the first sentence of the element's documentation
  string when present, with the full documentation string preserved verbatim in
  the body" (was: "MUST be sourced from the schema element's documentation string
  when present").

## 2. Body rendering

### 2.1 `# Schema` as the structural section

§4.2 gives `# Schema` conventional meaning — "structured description of an
asset's columns/fields" — and says conventional headings SHOULD be used when
applicable. We emit `## Fields` (`src/emit/render/body.ts:87,162`),
`## Arguments` (`:201`), `## Values` (`:140`), `## Members` (`:124`) and zero
`# Schema` across all bundles.

This has teeth beyond the prose: the reference tooling's `_schema_field_names`
helper parses top-level `# Schema` sections to extract backticked field names,
and its producer prompt mandates the heading. Any consumer reusing that helper
finds nothing in our documents today. `GOAL-6.1` does not mandate a heading name,
so this is free.

Every structural section moves under a single top-level `# Schema` heading. This
is deliberately a second H1, below the `# <Name>` title — that is what §4.3's own
example does, and it is what the reference helper scans for. Field names stay
backticked inside the table so the helper extracts them.

| Concept kind | Content under `# Schema` |
| --- | --- |
| `object`, `interface` | Fields table (`Field \| Type \| Description`); then `## Arguments` if any field takes arguments |
| `input` | Fields table (`Field \| Type \| Default \| Description`) |
| `enum` | Values table (`Value \| Description`) |
| `union` | Members table (`Member`) |
| `query`, `mutation`, `subscription`, `directive` | Arguments table (`Argument \| Type \| Default \| Description`) |

Field arguments are the one case a flat table cannot hold. Rather than an
unreadable `Arguments` column, fields that take arguments get an `## Arguments`
subsection below the fields table, with one `### \`fieldName\`` group each holding
its own arguments table. Fields without arguments contribute nothing, so for most
types the section is absent entirely and the diff stays small.

Non-structural body content — the description line, `Directives:`, `Implements`,
`Implemented by`, `**Returns**`, `Locations:`, `Repeatable.`, the scalar note and
the deprecation block — keeps its current position, outside `# Schema`.

### 2.2 Cell safety, and the fix for multi-line descriptions

`src/emit/render/body.ts:50-52,56-64` concatenate a raw GraphQL docstring into a
single-line bullet without collapsing newlines. 339 emitted bullets are followed
by a continuation line that escapes the bullet. The worst case is
`okf/shop-api/types/objects/Product.md:22-26`, where the `description` field's
docstring contains a paragraph break: the blank line terminates the `## Fields`
list, `May contain Markdown…` renders as a top-level paragraph, and the remaining
eight fields restart as a separate list.

A single `collapse()` helper is applied to every description used in an inline
position — table cells, `descSuffix`, index summaries:

1. `\s*\n\s*` → `" "`
2. `|` → `\|`

Rendering fields as table rows is what fixes this structurally: a paragraph break
in a docstring can no longer terminate a list, because there is no list. This
also satisfies §4.2's SHOULD to favour structural markdown.

`descriptionLine()` (`src/emit/render/body.ts:38-40`) — the concept-level
verbatim docstring — is explicitly **not** collapsed. `GOAL-6.3` requires it
faithful, and it is the only place the full text survives now that frontmatter
carries one sentence.

Deprecation stays inline as today's `(deprecated: <reason>)`, appended to the
Description cell after collapsing, so `GOAL-6.1`'s requirement that deprecation
and its reason be surfaced is unaffected by the reshape.

### 2.3 Tombstone heading levels

`src/reconcile/tombstone.ts:39` emits `## Last known definition` and then splices
a preserved region that opens with `# <Name>` — an H1 nested under an H2
(`okf/shop-api/types/objects/GiftCard.md:15-19`), which confuses heading-based
chunkers.

Fix by promoting the wrapper to `# Last known definition`, leaving the preserved
bytes untouched. Demoting the preserved headings instead would rewrite
human-visible content we have promised to preserve verbatim and would make the
tombstone body a lossy copy.

### 2.4 Index entry format

§6's sample is `* [Title](relative-url) - short description`; we emit
`- [Label](link) — summary` (`src/emit/render/directory-index.ts:10-14`, visible
at `okf/countries-api/types/objects/index.md:4`). Semantically identical
markdown, but both the bullet marker and the separator differ from the one
pattern a naive index parser would be written against.

`src/emit/render/directory-index.ts` switches to the §6 form exactly. Summaries
become the collapsed first sentence, which now equals the frontmatter
`description` — so `firstLine()` at `src/emit/bundle.ts:36-38` is deleted rather
than reimplemented.

### 2.5 SDL-sourced `resource` must be a URI

`src/source/sdl.ts:39` returns the filesystem path verbatim, and
`src/index.test.ts:124` asserts it as-is. §4.1 defines `resource` as a URI.

`src/source/sdl.ts` returns `pathToFileURL(resolve(filePath)).href`, which is
what makes the per-concept fragment of §1.3 a well-formed URI.
`src/index.test.ts` updates accordingly.

## 3. Reconciler

### 3.1 The frontmatter parser: parse to identify, splice to serialize

`GOAL-5.5` (round-trip without losing fields) and `GOAL-8.3` (preserve human
edits) are both MUSTs, and both are broken today.
`src/reconcile/frontmatter.ts:2` parses the preamble with a line regex:

```
const KEY_PATTERN = /^([A-Za-z_][A-Za-z0-9_-]*): ?(.*)$/;
```

Any frontmatter line that is legal YAML but does not match is glued onto the
*previous* entry (`frontmatter.ts:43-47`), and `mergeFrontmatter` then discards
the combined entry if that previous key is machine-owned (`frontmatter.ts:77-80`).
Confirmed loss cases:

- `gql.kind: object` — dotted key
- `my key: value` — key containing a space
- `"quoted key": value`
- a YAML comment line (`# owner: platform`)
- any non-matching line appearing first in the block (key `""`, filtered at
  `frontmatter.ts:77`)

`src/reconcile/frontmatter.test.ts` only covers a plain-identifier key
(`owner: platform-team`), which is why this is invisible today.

**Dependency.** The fix parses with the `yaml` library. `yaml@2.9.0` is present
in the pnpm store as a transitive dependency but is not hoisted, so it is not
importable — this adds `yaml` as the package's second direct runtime dependency,
after `graphql`. It is zero-dep and small; the trade is accepted for a MUST-level
correctness bug.

**We do not round-trip through `yaml.stringify`.** Re-serializing an AST would
reformat lines nobody touched, risking `GOAL-8.1` idempotence and `GOAL-8.6` diff
reviewability. Instead:

1. `yaml.parseDocument(preamble)` yields the top-level pairs, each carrying
   `range` byte offsets.
2. Each pair maps to an exact source slice, extended backwards to cover its
   `commentBefore` and any preceding blank lines, so nothing between pairs is
   orphaned.
3. Pairs whose key is in `MACHINE_KEYS` are dropped from the existing side. Every
   other byte range is copied **verbatim** into the merged block.

This fixes all five loss cases while keeping byte-exact preservation. Block
scalars and nested maps are handled for free, which the regex never was.

**Unparseable preamble.** If `parseDocument` reports errors, the entire existing
preamble is preserved verbatim, the merge is skipped for that file, and the file
is reported in the run result. Losing human data is the MUST; a stale machine
field is recoverable, a deleted human key is not.

`frontmatterValue()` and `withoutTimestamp()` are reimplemented on the same
identify-and-splice primitive so there is one parsing path, not two.

**Non-root `index.md` frontmatter is intentionally not preserved.** B renders
every non-root `index.md` with no frontmatter block at all (OKF §6 requires
non-root indexes to carry none). `mergeFrontmatter`'s `renderedBlock === null`
branch (`frontmatter.ts:136-138`) therefore returns `rendered` outright for
these files: there is no machine-owned block to splice preserved keys into, so
any frontmatter a human hand-adds to a non-root `index.md` is silently dropped
on the next reconcile. This is deliberate, not an oversight — a human adding
frontmatter to a non-root index is adding something the spec forbids there, so
removing it keeps the bundle §6-conformant. Root `index.md` is unaffected: it
always renders a frontmatter block, so the normal merge/preserve path applies.

### 3.2 Index writes must be reported

The `okf_version` loss verified in the issue had two halves. The merge dropped
the block — and `src/reconcile/plan.ts:99-101,126-129` deliberately excludes
index actions from both the result and the log, so the run reported
`unchanged: 10` with no `log.md` entry while destroying data.

Both halves are fixed. §1.5 stops the merge from discarding the block; and index
writes are counted in the run result, so a rewrite can never again be invisible.

Index changes stay out of `log.md`'s per-concept lists: indexes change whenever
their concepts change, so listing them individually would be pure noise on every
run.

### 3.3 `log.md`

§7 requires date headings in ISO 8601 `YYYY-MM-DD` form, and §9 point 3 makes
reserved-file structure part of conformance. `src/reconcile/log.ts:21` emits a
full timestamp (`## 2026-07-24T13:14:12.015Z`, see `okf/countries-api/log.md:1`).
Because the heading carries time-of-day we also never group entries by day, which
is the structure §7 describes. Three further gaps in the same file: entries are
appended at the end rather than newest-first, there is no `# Update Log` H1, and
the file has no frontmatter — so the reference viewer walks it as a concept and it
lands in the graph as `type: Unknown` (it only skips `index.md`).

The file becomes:

```markdown
---
type: Log
---

# Update Log

## 2026-07-25

### 13:14:12.015Z

**Added**

* [`Country`](types/objects/Country.md)
```

- `## YYYY-MM-DD` satisfies §7's MUST.
- Time-of-day moves to an `###` sub-heading rather than being dropped, so two
  runs on the same day stay distinguishable.
- `type: Log` matches the reference sample bundle and removes the junk graph
  node. The spec does not require it; it is convention-from-code, and it is three
  lines.
- Bullets use `*` to match §6/§7's sample form, consistent with §2.4.

Newest-first makes the file read-modify-write. That is fine: the append-only
rationale recorded at `docs/superpowers/specs/2026-07-24-reconciler-design.md:264`
was premised on never re-reading the file, and day-grouping requires a
read-modify-write regardless.

Insertion stays deliberately dumb: find the first `## ` heading after the H1; if
it is today's date, insert the run block directly after it; otherwise insert a
whole new date section at that position. Either way the change is a single
insertion hunk in git, so `GOAL-8.6` holds.

The existing bundles are not special-cased. Regeneration (§5) rewrites `log.md`
from scratch, replacing the old full-timestamp headings in the same commit.

## 4. Testing

TDD throughout, per `CLAUDE.md`: a failing test first for every item above. The
enforced coverage gate — lines/functions/statements ≥ 90%, branches ≥ 85% — is
the real bar, and the new table-rendering branches are where thin tests would
show.

The tests that carry the most weight, because they are the ones that would have
caught these bugs:

- **Frontmatter round-trip**, one case per confirmed loss in §3.1:
  `gql.kind: object`, `my key: value`, `"quoted key": value`, a `# comment` line,
  and a non-matching line appearing first in the block. Plus an unparseable
  preamble, asserting the block is preserved untouched.
- **`okf_version` survives a round-trip** on the root index — added by hand,
  re-run, still present — and the run *reports* the index write.
- **YAML 1.1 timestamp semantics**: parse emitted frontmatter with `yaml` in
  `version: "1.1"` mode and assert `timestamp` and `removedAt` come back as
  `string`, not `Date`. This tests the actual failure mode (`gray-matter`,
  `json.dumps`) rather than merely asserting quote characters.
- **Table cell safety**: a description containing a paragraph break, and one
  containing a `|`, each render as a single intact row.
- **First-sentence rule**, table-driven: no terminator; trailing terminator;
  terminator mid-line; multi-paragraph; whitespace-only → `null`; `null` → `null`.
- **`resource` anchors**: named type, root operation field under a renamed root
  type (`schema { query: RootQuery }`), directive, and an origin that already
  carries a fragment.
- **OKF §9 conformance** over the example schemas: every emitted file has
  parseable frontmatter and a non-empty `type`, and every internal link resolves.
  Since there is no upstream OKF validator, this check only exists if we write it.
- **Idempotence** (`GOAL-8.1`): re-running against the regenerated bundle is
  byte-identical, with no `log.md` entry. This is the guard on the `log.md`
  read-modify-write rewrite.

## 6. Non-issues, recorded so they are not "fixed" later

- **Relative links are correct; do not switch to the spec-recommended absolute
  form.** §5.1 calls `/path/to.md` the recommended form, but the OKF reference
  viewer explicitly discards any link target starting with `/` — switching would
  silently zero out our entire edge graph (measured: 62 / 162 / 14,527 edges). It
  would also render broken on GitHub, where a leading `/` resolves to the repo
  root, not the bundle root, and we ship bundles at `okf/<name>/` inside a larger
  repo. No code action; the emitter design doc's citation is corrected and the
  deviation stated with this reason.
- **Index summaries use the first sentence of the description**, matching the
  concept frontmatter exactly. §6 asks for a "short description"; this is it.
- **Reserved-filename defence is solid.** `src/model/naming.ts:38,68-72`
  case-folds every basename and hashes anything folding to `index`/`log`;
  verified with `type Index`, `type Log`, and fields `index`/`log`/`INDEX`.
  `naming.ts:76-83` throws on hash collision rather than overwriting.
- **Concept bodies link to `<rootDir>/index.md`** when a field references a root
  operation type (`src/model/project.ts:128-131`) — a link into a reserved
  non-concept. Latent (no example schema triggers it) and §7's own sample does the
  same. Leave it.
